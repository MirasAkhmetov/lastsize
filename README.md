# LastSize

Маркетплейс распродаж одежды и обуви в Казахстане: все распродажи магазинов в одном месте.

Спецификация продукта: [Lastsize Blueprint](https://claude.ai/artifact/6XgYfayz5mZaQvQ5nSdHDG).

## Стек

| Часть          | Технологии                                                           |
| -------------- | -------------------------------------------------------------------- |
| Сайт           | Next.js 16 (App Router), React 19, Tailwind CSS 4, next-intl (ru/kk) |
| API            | NestJS 12 на Fastify, zod                                            |
| Данные         | PostgreSQL 18, Redis 8, S3-совместимое хранилище (SeaweedFS)         |
| Инфраструктура | Docker Compose, Caddy (HTTPS), GitHub Actions                        |

## Структура

```
apps/
  api/          NestJS API (/api/v1). Единственная точка доступа к данным
  web/          Витрина и кабинет продавца на Next.js (ru/kk). Работает только через API
  admin/        Админка на Next.js (только для сотрудников, вход с кодом из приложения)
packages/
  config/       Проверка переменных окружения при старте
  contracts/    zod-схемы запросов и ответов API
  ui/           Дизайн-система: токены, компоненты (кнопки, поля, цены, размеры, карточка товара, шторка, toast)
  domain/       Бизнес-правила без ввода-вывода: переходы статусов магазина, адреса (slug)
  db/           Схема PostgreSQL (Drizzle), миграции, справочники, RBAC, репозитории остатков и цен
  logger/       pino со скрытием секретов
deploy/         Production: docker-compose.prod.yml, Caddyfile, пример .env
```

## Запуск для разработки

Нужны Node.js 24 (`.nvmrc`) и Docker.

```bash
corepack enable
cp .env.example .env
pnpm install
pnpm infra:up      # Postgres (порт 5433), Redis, S3
pnpm db:migrate    # миграции + справочники (роли, категории, размеры, цвета)
pnpm dev           # всё сразу: API, фоновый worker, сайт и админка
```

| Что                                  | Адрес                                           |
| ------------------------------------ | ----------------------------------------------- |
| Сайт (ru / kk)                       | http://localhost:3000, http://localhost:3000/kk |
| Кабинет продавца                     | http://localhost:3000/seller                    |
| Дизайн-система (только в разработке) | http://localhost:3000/design                    |
| Админка                              | http://localhost:3001                           |
| API                                  | http://localhost:4000/api/v1/health             |

Сайт и админка проксируют `/api` на API, поэтому браузер всегда работает со своим доменом.

## База данных

- Схема описана в `packages/db/src/schema`. После её изменения: `pnpm db:generate` создаёт SQL-миграцию в `packages/db/migrations`. Миграции коммитятся, CI проверяет, что они не отстают от схемы.
- Триггеры и функции пишутся вручную: `pnpm --filter @lastsize/db exec drizzle-kit generate --custom --name <name>`.
- Деньги хранятся целыми числами в тиынах (1 ₸ = 100 тиын).
- Остатки меняются только через `reserveStock` / `releaseStock` / `commitStock` / `returnStock` / `setStockLevel`. Каждое движение пишется в журнал `inventory_transactions`, который нельзя изменить или удалить. Ограничения в самой базе не дают зарезервировать больше, чем есть.
- Скидка (`discount_percent`) считается базой от минимальной из цен: заявленной, за 30 дней и фактической на WB/Kaspi. Каждое изменение цены триггер пишет в `price_history`.

## Товары и фото

- Фото загружаются в API (`POST /seller/stores/:id/media`, до 15 МБ). Тип файла проверяется по содержимому, EXIF и координаты удаляются, ориентация применяется. Получаются 320/640/1080 px в AVIF и WebP в публичном бакете, оригинал хранится в приватном. В PostgreSQL только ключи.
- Фото отдаются по `/media/products/<магазин>/<фото>/<ширина>.<avif|webp>`: в production это делает Caddy, только этот шаблон пути и только чтение. В разработке Next.js проксирует `/media` на filer SeaweedFS (`MEDIA_ORIGIN_URL`).
- Опубликовать товар можно, если магазин подтверждён, есть фото, хотя бы один размер в наличии и скидка не меньше минимальной (`catalog.min_discount_percent`, по умолчанию 30%).
- Скидка при снижении цены считается от самой низкой цены, которую покупатели видели за 30 дней. Правки в черновике не учитываются. Повышение цены до скидки больше чем на 10% и скидка 80%+ у нового магазина ставят флаг для модератора.
- Публикация без премодерации: модератор видит ленту новых товаров и товаров с флагами и может снять товар с причиной. Вернуть снятый товар может только модератор.

## Перенос товаров (импорт)

Раздел продавца «Перенос товаров» (`/seller/import`), доступен только владельцу магазина (`integration:manage`).

- **Wildberries**: продавец вставляет API-токен (только чтение: «Контент», «Цены и скидки», «Маркетплейс»). Токен проверяется запросом к WB, шифруется AES-256-GCM ключом `SECRETS_ENCRYPTION_KEY` и больше не возвращается: API отдаёт только последние 4 символа. Берутся карточки, цены (если WB отдаёт их в KZT) и остатки со складов продавца (FBS). Адреса API WB задаются `WB_*_API_URL`, по умолчанию боевые.
- **Kaspi**: ссылка на XML-прайс. Офферы по размерам объединяются в товары по названию. Фото в прайсе Kaspi нет, их добавляют в мастере.
- **Excel / CSV**: одна строка — один размер, шаблон лежит в `apps/web/public/templates/lastsize-import.csv`. CSV в UTF-8 или Windows-1251, `;` или `,`.
- Мастер: сопоставление категорий, цветов и размеров (выбор запоминается для магазина) → скидка от цены на маркетплейсе с округлением до …90 ₸ → публикация пачками по 2 товара. Одна строка не может стать двумя товарами: строки забираются в работу атомарно. Повторная загрузка пропускает уже перенесённые товары.
- Цена на маркетплейсе сохраняется в варианте (`external_price`) и участвует в расчёте скидки: нельзя показать −50% от завышенной цены, если на WB товар дешевле.
- Ссылки на прайс и фото скачиваются только с публичных адресов: проверяются схема, порт и все IP из DNS (в том числе после редиректов), есть ограничения размера и времени. `IMPORT_ALLOW_PRIVATE_HOSTS=true` разрешает локальные адреса только для тестов и не принимается при `NODE_ENV=production`.

## Синхронизация остатков

Отдельный процесс `worker` (`apps/api/dist/worker.js`, тот же образ, что и API) выполняет фоновые задачи из очереди BullMQ в Redis. В разработке `pnpm dev` запускает его вместе с API.

- Каждые 10 минут проверяются все подключения, у которых есть перенесённые товары. Продавец может запустить проверку вручную и посмотреть журнал (`sync_runs`, хранится 30 дней).
- Изменение остатка на маркетплейсе с прошлой проверки (продажа или правка там) применяется к нашему остатку как разница, так продажи с обеих сторон складываются. Забронированные у нас единицы не списываются: если маркетплейс продал и их, остаток останавливается на брони, а в журнале появляется предупреждение.
- WB: можно выбрать свой склад (FBS) и включить «Обновлять остатки на WB». Тогда наш свободный остаток (в наличии − бронь) записывается на WB после проверки и через несколько секунд после правки остатков продавцом. Нужен токен с правом записи. Смена склада начинает отсчёт заново, без скачка.
- Kaspi: остатки только читаются из XML-прайса.
- Цена на маркетплейсе обновляется. Если из-за её снижения скидка опубликованного товара стала меньше минимальной, товар получает флаг `discount.externalPriceDropped` для модератора.
- Одна синхронизация на подключение одновременно: дедупликация в очереди плюс захват строки в базе. Упавшая синхронизация считается брошенной через 15 минут.

## Вход и права доступа

- **Продавцы и сотрудники**: телефон + пароль (argon2id). Сессия хранится на сервере, в cookie только случайный токен (`__Host-sid`, HttpOnly, Secure, SameSite=Lax). Сессия продавца живёт 30 дней с продлением, сотрудника — максимум 8 часов.
- **Сотрудники (ADMIN, SUPER_ADMIN)**: после пароля обязателен код из приложения-аутентификатора (TOTP). Секрет TOTP хранится зашифрованным (AES-256-GCM, ключ `SECRETS_ENCRYPTION_KEY`), использованный код нельзя повторить.
- **Покупатели** не регистрируются: гостевая сессия создаётся при первом действии (`__Host-gsid`).
- **Доступ по умолчанию запрещён.** Любой эндпоинт требует вход, если он не помечен `@Public()`. Права проверяет сервер: `@RequirePermissions(...)` для глобальных прав, `@RequireStoreAccess(...)` для прав в конкретном магазине. Чужой магазин отвечает 404. Роли и права описаны в `packages/db/src/rbac.ts`.
- **Защита от перебора**: 5 неверных паролей на номер — блокировка на 15 минут, лимиты на IP для входа и регистрации, 5 неверных TOTP-кодов — блокировка.
- **CSRF**: изменяющие запросы с чужого `Origin` или с `Sec-Fetch-Site: cross-site` отклоняются.
- **Аудит**: входы, неудачные попытки, блокировки, выдача ролей пишутся в `audit_logs`. Запись нельзя изменить или удалить.

### Первый администратор

```bash
# локально
pnpm --filter @lastsize/api build
node --env-file=.env apps/api/dist/cli/create-admin.js --phone "+7 701 123 45 67" --name "Имя"

# на сервере
cd deploy && docker compose -f docker-compose.prod.yml run --rm api \
  node dist/cli/create-admin.js --phone "+7 701 123 45 67" --name "Имя"
```

Пароль вводится скрыто. При первом входе нужно подключить приложение-аутентификатор.

## Проверки

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

Интеграционные тесты API с настоящими Postgres и Redis запускаются, если заданы `TEST_DATABASE_URL` и `TEST_REDIS_URL` (в CI заданы всегда):

```bash
TEST_DATABASE_URL=postgres://lastsize:dev-only-change-me@localhost:5433/lastsize \
TEST_REDIS_URL=redis://localhost:6379 pnpm test
```

Тесты товаров и фото дополнительно нужны S3-хранилище (локально оно уже запущено через `pnpm infra:up`):

```bash
TEST_S3_ENDPOINT=http://localhost:9000 TEST_S3_ACCESS_KEY=lastsize-dev TEST_S3_SECRET_KEY=dev-only-change-me-minio pnpm test
```

Тесты `packages/db` создают для каждого файла отдельную временную базу, применяют миграции и удаляют её после.

## Развёртывание на сервере

```bash
cd deploy
cp .env.production.example .env   # заполнить, секреты: openssl rand -hex 32
docker compose -f docker-compose.prod.yml up -d --build
```

Перед стартом API контейнер `migrate` применяет миграции и справочники. Если миграция не прошла, API и worker не запустятся. Worker без HTTP-порта, перезапускается Docker при падении.

Наружу открыт только Caddy (порты 80/443, и 8081 для админки, пока нет домена: закройте его файрволом для всех, кроме своих IP). API, базы и хранилище доступны только во внутренней сети Docker. До покупки домена `SITE_ADDRESS=:80`.

## Правила безопасности

- Секреты только в переменных окружения. `.env` не коммитится, в репозитории только `.env.example`.
- Сайт не обращается к базе, очередям и внешним API напрямую. ESLint запрещает такие импорты в `apps/web`.
- Логи проходят через `@lastsize/logger`: пароли, токены, cookie и заголовки авторизации заменяются на `[REDACTED]`.
- Ошибки API отдаются в формате RFC 9457 без стектрейсов и внутренних сообщений.
